01THE PIPELINEsignal path

Every harvest round follows one signal path. Sources are fetched in parallel; each sample is inspected, reduced to its unpredictable digits, and absorbed into a single pool. Output is only ever a hash of that entire pool.

FIG.1 — the public-entropy signal path. Orange = the only private input.

Parity note: the browser instrument implements extraction, the freshness test and SHA-256 conditioning. The Python pipeline adds an adaptive-proportion health test and a Von Neumann debiasing stage — same architecture, fuller plumbing.

02TWO KINDS OF RANDOMthe core idea

"Random" hides two different properties. Unpredictability: no one can compute the value in advance. Secrecy: no one else can learn the value afterwards. Statistics tests measure the first. Keys require both.

FIG.2 — every remote lane lives on the floor of this chart. That floor is why the receipt says NON-SECRET, and why wallet mode is built on the top-right dot.
03EXTRACTIONwhere the jitter lives

A pressure reading like 1002.4 hPa is mostly predictable — any forecast gets you the "1002". The chaos hides in the tail. So the extractor throws the confident digits away and keeps only the last ones, from every field, across every source.

FIG.3 — boxed digits enter the pool; the rest never do.

One discipline applies on top: the one-clock rule. Nearly every API also returns a "now" timestamp. If every lane extracted its clock digits, thirteen "independent" sources would secretly share one input — your clock — and the independence claim would collapse. Exactly one lane (quakes) may extract time; all others strip it.

04HEALTH + THE HAIRCUTtrust nothing

A lying source is worse than a dead one. Before crediting a sample, the pool checks it: a fetch identical to the previous one (a CDN cache hit, a stale feed) is credited zero bits. A dead lane simply contributes nothing — the pipeline never crashes, it just gets thinner.

Diversity is enforced the same way. Ten weather feeds are one source wearing ten hats, so no single domain may account for more than 40% of the pool's credited entropy, and the pool refuses to emit below five domains:

FIG.4 — the 40% domain haircut.
05MIXINGnot merging, not stitching

Samples are never laid side by side. Each is hashed with its source name into one pool, and the output is SHA-256 over the entire pool — so every output bit depends on every input bit from every lane simultaneously. This is the avalanche effect. Test it:

flipped last character → … of 256 output bits changed≈50% = ideal
FIG.5 — live: SHA-256 of your text vs. the same text with one character changed. Orange cells are bits that differ.

Formats are lenses, not entropy. HEX, Base64, UUID v4, integers, dice and lotto picks on the instrument are all deterministic encodings of the same 32-byte emission — integer-like formats via rejection sampling, so no modulo bias. Switching format never re-emits; the transcript always verifies the raw bytes.

06WALLET MODEthe full toolchain

Everything above produces NON-SECRET output, because every remote lane sits on the floor of FIG.2 — an observer can replay public feeds. Key material inverts the architecture: in the Python toolchain, the OS CSPRNG is the unconditional foundation, and harvested entropy is mixed in on top through HKDF, which can add security but mathematically cannot remove it.

FIG.6 — a test in the repo fails the build if any code path ever skips the black box.

Even then: generate on an offline machine, write the words on paper or steel, and for serious holdings prefer a hardware wallet's audited generation. This project exists so you understand the process — stated limits are a feature.

The browser exception: the instrument's KEY/PW output is SEALED class — the same architecture in miniature: an unconditional base from the browser CSPRNG with the emission hashed in on top. Non-reproducible by design, never logged, never in transcripts. Fit for passwords and API keys; wallet seeds still belong to the offline Python toolchain.

07PROOFtranscripts · anchors · seals

Fairness here is a proof, not a promise. Every emission can export a verifiable transcript: the ordered hash of every absorbed sample (duplicates included, marked), the pool fingerprint, the emission nonce, the drand round, and the output. entropy-forge verify transcript.json recomputes the entire chain offline — no trust in the page, the server, or these pixels required.

FIG.7 — the transcript chain. Tamper with any entry, the fingerprint, or the output, and verification fails loudly.

Three artifacts travel with each receipt: the fingerprint (commit — publish it before a draw), the drand round (freshness — the output provably postdates it), and the seal — a deterministic dot-matrix glyph of the output bytes, because humans compare shapes faster than hex. The instrument's INSPECTOR shows the same machinery live: the ledger (credit accounting, haircut drawn), the tape (raw digits as absorbed; operator strokes deliberately redacted), and the pool buffer with its live fingerprint. An adversary drill in demo mode replays frozen data through two lanes so you can watch the freshness test zero them — defenses you can see firing.
